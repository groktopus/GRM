# Internal QueryInput and cooperative worker slice

This slice implements only the closed QueryInput decoder and a finite batch worker primitive. It is not a usable CRM, MCP server, installation-wide scheduler, or evidence of whole-MVP acceptance. Independent API/QE review is required before production integration.

## Boundary behavior and findings

`internal/queryinput` ports the reviewed GRO-34 boundary, with the GRO-35 findings addressed:

- Applicable leap seconds preserve their exact UTC seconds text in `Instant`, rather than passing through `time.Time`. Fixed-width UTC values can be ordered lexically; this does not implement temporal retrieval. Adjacent `:59`, `:60`, and midnight remain distinct. Calendar checks remain mandatory. The historical leap table matches [IERS Leap_Second.dat](https://hpiers.obspm.fr/iers/bul/bulc/Leap_Second.dat), updated through Bulletin C72, July 2026. Unknown leap boundaries reject; no future leap prediction or online update is performed. A later announced insertion requires a reviewed table update. Negative-leap handling is unimplemented because none has occurred; an announcement requires review before relying on affected timestamps. This remains an operational integration limitation identified by GRO-36.
- Valid Unicode, combining marks, spaces, newlines, binding order, optional field presence and continuation cursor receive permanent decoded-value assertions. Go `encoding/json` replaces unpaired escaped surrogates with U+FFFD. Tests characterize this interoperability limitation and accept legitimate U+FFFD. No lossless arbitrary UTF-16 guarantee is made.
- Required/null/type combinations, exact codepoint/collection/token/ID/page endpoints, closed alternatives, decoded-name duplicates, trailing data and invalid-result zeroing receive regressions. Explicit empty bindings remain distinguishable from omission. No defaults are fabricated.
- 145 differential fixtures are generated by Python JSON Schema 2020-12 validation of the complete normative registry with QueryInput as root and format checking enabled. The checker rejects leap seconds, so applicable-leap assertions use GRO-36 separately. Duplicate keys, request bytes and transport framing are outside schema object-instance comparison. The fixture suite is finite; full schema equivalence is not claimed.

`internal/worker` ports the reviewed join/cancel primitive. Each call permits 1–2 worker slots and at most eight additional waiting batch entries; excess rejects before dependency calls. There is no producer or per-job goroutine. Jobs are caller-owned and must remain unchanged until return. The first recorded dependency error cancels siblings; every worker joins before return. Parent cancellation/deadline takes precedence at return, and wrapped errors retain `errors.Is`/`errors.As`. A dependency must cooperate with context: noncooperative I/O can delay return indefinitely. Tests include permanent independent sibling-failure and typed-error probes from GRO-35, cancellation after an entry handshake, deadlines, exact batch bounds and serial execution.

These are per-call bounds. Future MCP integration must enforce the installation-wide **two executing/eight waiting/one writer/one internal-model job** limits across all invocations. A serial worker invocation does not establish global writer or model exclusion. This slice does not install a new GRM admission policy.

## Build and verification

The root module pins `go 1.27.4`. There are no direct or indirect Go module dependencies and no go.sum. No SDK/storage/crypto/model dependency is introduced. `go mod tidy` removes the redundant same-version toolchain directive; use `GOTOOLCHAIN=local` with the verified Go 1.27.4 installation.

```sh
GOTOOLCHAIN=local go vet ./...
GOTOOLCHAIN=local go test -count=1 ./...
GOTOOLCHAIN=local go test -race -count=1 ./...
GOTOOLCHAIN=local go test -race -count=20 ./internal/worker
GOTOOLCHAIN=local go test ./internal/queryinput -run='^$' -fuzz=FuzzParseQuery -fuzztime=5s -parallel=2
govulncheck ./... # pinned golang.org/x/vuln v1.10.0 review tool
```

`gofmt -l internal` must produce no output. The development-only Python oracle uses the pinned versions in `tools/oracle-requirements.txt`; it is not imported by the Go product. Install those in an isolated environment, then run `python tools/queryinput_oracle.py` from any directory and review the fixture diff. Python checker limitations are explicit above. No Python package, tool binary, acquisition archive or raw build log is committed as product code.

Exact tool provenance, source hashes, check logs and results are delivered in GRO-37's evidence artifact and task document. Go archive SHA-256 is `7226736c2339719cda28fbf3a54d71aa63bcefe376e98cef00034268dab24840`; reused binaries are checked against archive members rather than downloaded again. Scanner build metadata and Python package acquisition hashes are recorded separately. Fuzzing checks panic freedom/union shape, not exhaustive equivalence. Race testing covers exercised schedules only. No release, independent certification, storage, cryptography, model execution, full MCP transport or whole-MVP result is claimed.
