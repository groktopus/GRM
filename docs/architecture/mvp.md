GRM is one owner's relationship memory, reached through the owner's existing assistant. It owns natural-language capture interpretation and query planning internally. A10 is **omitted**: unrelated update queue/hints/acknowledgements are not implemented. Requested commitment queries remain core.

## Decisions, alternatives and consequences

| Decision | Selected shape and rationale | Rejected/deferred alternative and reopening evidence |
| --- | --- | --- |
| Runtime authority | One Go stdio process, one owner, one active assistant session, exclusive installation lock before discovery/data access. Atomic SQLite transactions own content and receipts. | Independent services/multiple writers create recovery and privacy coordination without demonstrated load need. A second process is rejected without mutation. A future daemon/remote transport requires a new approved design. |
| Persistence | SQLite on local ext4; WAL, synchronous FULL, foreign keys enabled. Selected text excerpts live in the same database transaction as claims/commitments. Online backup API with quiesced writes. | PostgreSQL is credible for growth; dedicated temporal graph/vector services add operating and synchronization boundaries. Reconsider on measured supported-limit failures, not graph vocabulary. |
| Retrieval | Typed exact/time/path/commitment plans; lexical plus exact dense passage ranking, equal-weight RRF constant 60, fragment-ID tie break. Evidence rendering is deterministic. | Lexical-only is a required comparison control, not assumed to pass paraphrase recall. No approximate vector store, reranker, answer-generation agent or graph framework. |
| Privacy | Same-host host/model execution, current policy before model dispatch/hydration/citation/publication. Source text is data. | Cloud fallback, telemetry, arbitrary URL fetch and model-controlled tools are excluded. Paid services or boundary changes go to CPO. |
| Restore | Independent current privacy/control authority plus surviving current witness; quarantine before activation. | Warning-only restore fails R2. Losing all trustworthy current control state sacrifices old-backup usability; empty new-lineage reset is not successful A12 recovery. |

These choices favor correctness and privacy over availability. Local inference, offline host compatibility and CPU deadlines remain unproven. Architecture approval must accept this as a qualification candidate, not a claim of working software. No Go delivery competence is established by documentation.

## Ownership, identity and evidence

Owner O is an ordinary person entity. People, organizations, places, things and events have immutable, opaque typed references with at least 128 random bits, never names as keys. Explicit references target only that identity. Rename retains prior aliases; Morgan Lee remains ambiguous across renamed M1 and M2. No automatic merge or update-by-name fallback. Missing/deleted references and malformed input cause no unrelated effects. New identity selection must be explicit; candidate-set revision changes invalidate stale previews.

Assertions carry typed participants/predicate, exact eligible supporting spans, valid-time precision, known interval and correction/conflict lineage. Attendance never creates all-pairs conversation; speaker, attendee and reporter are independent roles. The particular book has a separate identity from its title. Topic discussion does not prove expertise; a path does not prove direct acquaintance or willingness to introduce.

**Immutable citation binding (AE3/Q08): one wire SourceID permanently denotes one immutable selected body.** The source's version value is immutable for that body; source spans are half-open Unicode code-point offsets. Locator/timecodes describe provenance, not fetched content. Body replacement creates a new SourceID with internal source-family/version lineage; it never edits the old body in place. Source-family deletion targets every revision and every dependent source copy in that family. The helper preview enumerates that scope; it cannot silently delete independently supplied sources. An old citation resolves the exact old eligible body/span or explicit unavailable, never new text. Unknown speaker stays unattributed. No claim of checking a full original transcript that was never supplied.

Manual owner notes are archival under explicit capture intent; external excerpts require explicit copy authorization. Linked excerpts require a current owner-controlled eligibility grant; unknown/expired/revoked grant denies use. No automatic upstream permission detection is claimed. Mere upstream disappearance does not revoke an eligible archival copy. S9 is genuinely revoked, separate from the archival-disappearance fixture. Current access/deletion policy overrides all historical cutoffs.

Known timestamps are server-assigned UTC at commit, with commit sequence breaking ties. Known intervals are start-inclusive/end-exclusive; cutoff at a correction includes that correction. Valid intervals preserve supplied precision and uncertainty; month enclosure is an index aid, never an asserted first day. S3 shifts S2 start to September 15: September 10 at early cutoff supports Cedar Lab; at later cutoff no role is supported. September 16 is supported under both accounts. S4 independently conflicts rather than silently replacing Cedar Lab; S5 only becomes known November 1. Isolate S4 from A06.

## MCP, authority and atomic effects

The five tools and complete input/output shapes are in [MCP](mcp.md) and [schema registry](mcp-schemas.md): prepare, commit, query, read, operation status. Protocol target is MCP 2025-11-25, contract major 1, JSON Schema 2020-12, official Go SDK v1.7.0. Tools return equivalent structured and text content, explicit errors/partial/unknown states and inspectable evidence. No success is inferred from `applying`, cancellation or lost reply. Discovery hints are not authorization.

Prepare persists a bounded immutable preview, not CRM facts. Ordinary clear owner instruction can authorize inspected non-destructive commit; identities and uncertainty remain explicit. Commit validates all targets, versions, source policy and full plan then atomically writes identities, sources, assertions, promise, lineage and receipt. No successful prefix. Index work is derived and separately checkpointed; capture receipt distinguishes durable state from semantic readiness. Exact reads remain possible during semantic lag only when eligible and complete; topic queries disclose missing coverage.

Effective-owner UID, protected launch/configuration and stdio descriptors authenticate the one local session; require a protected launch credential binding and least capabilities as in MCP. Reject wrong UID, unsafe permissions/symlinks, revoked launch, second live lock and unsupported protocol before private output. Root and arbitrary same-UID code execution are outside the isolation promise. Qualified host exposes only GRM tools: no shell/filesystem/terminal-driving/extension-manager path to the operator key.

Deletion requires a trusted terminal grant in addition to `confirm:true`. Adopt the signed-grant correction in [trust](trust.md): Ed25519, separate encrypted private key, enrolled public key in independent protected control state. Bind **session and base_revision as well as every GrantPayload field** in the registry. Canonical order is the registry narrative order followed by session then base_revision; ASCII/base64url constrained values, no whitespace/duplicate/unknown fields, domain separator `GRM-OWNER-GRANT-1\n`. The local helper displays the server-produced complete plan safely, requires controlling-terminal approval, and never signs caller-substituted bytes. Grant lifetime <=5 minutes and <=plan expiry. Changed target/epoch/session/base/key/digest invalidates it. Restart invalidates unused grants. No grant/signature through MCP input.

Encrypted-key container binding: OpenSSH private-key format, Ed25519, bcrypt KDF with at least 64 rounds and AES-256-CTR, strong owner passphrase entered only in the controlling terminal. Use reviewed Go `golang.org/x/crypto/ssh` encrypted-key parsing, not a custom cipher/container or shell signing subprocess. Pin reviewed dependency/tool versions and verify format compatibility before governing approval. Private key is never in host/server environment, backups, exports or model context; server has verification key only. Protection depends on host/key/terminal integrity; no claim against malicious same-UID code.

## Replay, interruption and restoration of operation knowledge

Installation/owner/OpID scopes operation identity across restarts, not MCP request ID. While eligible, compare fully decoded/default-normalized prepare and commit inputs separately: object-key order ignored, array order and exact strings significant. Changed reading-list intent to travel itinerary conflicts. Prepared plan is immutable; same plan cannot apply under another OpID. Lost response after durable commit recovers the same result without model execution or another effect. Before durable domain commit no facts are changed; unknown commit remains applying until reconciled. Cancellation cannot undo a commit.

**Current control authority also reserves every accepted OpID before storing any preview/domain effect (Q05).** Extend operations' append stream with a distinct `operation_reserved` control record containing only random OpID and reservation timestamp, without request hash, source, person, plan or result associations. Its durable kit/witness checkpoint is advanced before preparation may persist or commit. Never expire a reservation. A reserved OpID whose database plan/receipt is missing after restore returns `REFERENCE_UNAVAILABLE` with OpID, zero model invocation and zero effects; do not call it committed when outcome is unknown. This intentionally sacrifices detailed retry recovery for ordinary updates lost under backup RPO. Existing eligible plans/receipts recover normally; deleted-dependent operations scrub to the specified committed-unavailable state when commit is known. Both identical and changed replays after scrub return unavailable without equality testing. Entire kit/witness loss blocks activation, never silently makes old IDs fresh. New operation identity is required for newly authorized intent; no semantic re-ingestion detector is promised.

Kit reservation append is not a CRM mutation success. Crash after reservation but before a prepared database record can leave an unavailable reservation; caller gets actionable instruction to inspect status and start a newly authorized operation only after verified no domain effect. Domain commit+receipt remains one SQLite transaction. The single server serializes overlapping requests; bounded in-process concurrent identical commit retries yield one effect. Independent sessions are unsupported and rejected without mutation as R4 permits.

## Deletion barrier, durable authority and old backups

Adopt operations revision-2 protocol: installation starts CLOSED, holds installation/kit locks, validates actual configured mounts and owner-only paths, authenticated log and independent heads, then replays denials before opening content. Required kit is on existing independent owner-controlled storage; local witness lies outside content backup scope; designated independent current witness is required for host-loss recovery. Missing mount never causes fallback creation on root disk.

For deletion/revocation: close admission/publication, drain/cancel in-flight work; persist CLOSED marker with file+directory fsync; append framed authenticated control record and fsync log; atomically advance kit head then each required witness with file/rename/directory fsync; apply all denials, scrub dependent plans/replay payloads and update applied head in SQLite WAL/FULL transaction; clear model slots/restart processes when needed; discard/rebuild indexes; run probes; persist validated head and open only when heads agree. A durable denial is never undone because acknowledgement was lost. Failure leaves closed/pending, no false success.

Bind integrity algorithm to HMAC-SHA-256 with independent random 256-bit kit key. Length frame is 8-byte unsigned big-endian payload byte count followed by canonical UTF-8 JSON control record and 32-byte HMAC over domain-separated frame+payload. Reject oversize frame (>64 KiB), unknown fields/type/version, broken sequence/previous-head chain or authenticator. Hash chain covers control metadata only; no deleted-content digest. Kit key is protected independently of snapshots; it is not the terminal signing key. This is integrity relative to trusted state, not freshness proof. Simultaneous rollback of all heads is undetectable without an external anchor; if current custody cannot be established, quarantine. No risk-acceptance bypass.

S7 deletion erases old and corrected excerpt/topic/attributions and dependent content from current/history/topic/read/citation/plan/receipt/cache/model/export paths. Only per-source opaque reference, deletion status and recorded/deletion timestamps survive. System control envelopes and independent random operation reservations do not retain source/person linkage. Revocation uses a separate random eligibility-grant control record. Mixed derivations are rebuilt from remaining eligible supports; unrelated records survive.

B0 restore is offline quarantine: validate lineage/schema/checksums, obtain complete current kit plus surviving independently current witness, replay denials and operation reservations, discard old indexes/grants, validate references and both times, probe S7/S9 and unrelated records, then promote. No read/MCP/model/export route before validation. Missing/stale/mismatched kit/witness blocks activation. Recollection or B0's own ledger is insufficient. Abandoning B0 for empty new lineage is safe reinitialization and failed full restore, never A12 pass.

## Native export/import v1 and lifecycle

Bundle is a directory, no executable/archive extraction semantics. Exact streams: `entities.jsonl`, `sources.jsonl`, `claims.jsonl`, `commitments.jsonl`, `reservations.jsonl`, `tombstones.jsonl`; plus `manifest.json`. UTF-8, LF, one closed JSON object per line, no duplicate keys/nonfinite values. Unknown major or unknown fields/record types are rejected; v1 changes require reviewed compatibility disposition, not silently ignored private fields.

Manifest closed required fields: `format`="grm-native", `major`=1, `lineage` opaque string, `application_version` string, `schema_version`=1, `owner` EntityID, `owner_timezone` IANA name, `snapshot_revision` Version, `created_at` Instant, `control_head` {sequence nonnegative integer, head base64url string}, `files` array containing exactly the six named streams with {name, byte_size nonnegative integer, record_count nonnegative integer, sha256 64 lowercase hex}. No credentials, active keys/grants, logs, vectors, caches or model assets. Checksums detect accidental corruption, not source authorization.

Each record has exact `record` discriminator and fields:

| Stream / record | Required fields and types |
| --- | --- |
| entities / entity_version | `entity`: MCP Entity; `known_from`: Instant; optional `known_until`: Instant; `evidence`: StoredEvidence[] (empty only for explicit setup identity). Preserve all eligible historical name versions. |
| sources / source | `id`: SourceID; `family`: opaque random string; `version`: Version; `mode`: owner_note/authorized_copy/linked; `locator`: Label; `body`: Body; `recorded_at`: Instant; `eligibility`: {grant: random string, state:"eligible", recorded_at:Instant, expires_at?:Instant}. One body per immutable SourceID; no ineligible source bytes or identifying locator. |
| claims / claim_version | `claim`: MCP Claim with stable-only participants/evidence. Knowledge version is identified by `(claim.id, claim.version)`, unique; supersedes must resolve or have an unavailable marker. |
| commitments / commitment_version | `commitment`: MCP Commitment; unique `(id,version)` preserving all eligible state transitions and both time dimensions. |
| reservations / operation | `operation_id`: OpID; `state`: "reserved_unavailable"; `recorded_at`: Instant. Portable import deliberately does not carry replay fingerprints or executable prepared plans; every exported reserved identity remains non-executable. This loss of receipt detail is explicit, not a lost domain change. |
| tombstones / unavailable | `ref`: Ref; `state`: "deleted" or "ineligible"; `recorded_at`: Instant; `deleted_at`: Instant only for deleted. No identifying fields or source/person mappings. |

All field types reuse MCP definitions; no additional properties. `record` is required in each row. Count/checksum bytes are exact stream bytes; validate all before opening data. Referential integrity covers identity participants, source spans, owner, corrections and lineage; a missing content reference requires a matching content-free unavailable row or fails import. No dangling identity reference may be silently invented. Validate real dates, half-open intervals/precision, span boundaries, entity kinds, unique version tuples and matching lineage/current control state. Unknown source eligibility denies use. Current kit dominates manifest/checkpoint; import cannot assert that an old manifest is current or launder an uncertain lineage into a new one. Restoring same lineage preserves IDs; foreign live lineage import/merge is unsupported.

Export uses coherent snapshot and publication privacy barrier; deletion invalidates unpublished bundle and staging bytes. Write temporary owner-only directory, validate, then atomic promotion on same filesystem. Import stages in quarantine and uses B0 gate, rechecks eligibility, scrubs denied sources and imports all reservations as unavailable. Credentials re-enrolled separately. Backups use database snapshot plus manifest, not portable export; acknowledged ordinary updates may have <=24h loss with verified daily backup, while no acknowledged denial may reverse. Restart target 5min/host restore target 4h after prerequisites are engineering targets, unmeasured and unbounded when current control authority is unavailable.

Content-free logs expire at 7 days. Rolling encrypted backups: 7 daily/up to 4 weekly only within hard 30-day age; kit/witness control state persists while any lineage copy is recoverable. Owner-held exports, immutable media and assistant conversations remain separate copies; document disposal, no forensic erasure guarantee. Upgrade/migrate in quarantine with prior backup, current kit and schema compatibility; failed candidate leaves live state intact. Rollback never rolls back privacy/control state. Uninstall distinguishes binary-only removal from owner-confirmed data/secret/kit/media disposal; retain authority until every recoverable old copy is retired.
