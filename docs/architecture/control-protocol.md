# Persistent control and publication protocol v1

[Durable domain watermark](domain-watermark.md) is normative over earlier domain-counter, control-kind and recovery statements. It adds the fourth closed control kind and pre-transaction durable revision reservation; historical no-reuse claims use this protocol.

Status: proposed corrective architecture, normative over earlier control/key/publication prose in MVP, operations and trust. Resolves B02/SEC-01/O1–O3 and specifies capacity/key-policy corrections SEC-02/O5. No implementation or cryptographic/runtime verification is claimed. The exact immutable commit and fixture vectors require independent review before final freeze.

## Closed record and byte grammar

All control values are ASCII. Reject unknown/duplicate fields, null, floats, nonfinite numbers, extra objects, escapes, whitespace and trailing bytes. JSON bytes are the fixed ordered keys below, compact separators `,` and `:`, double-quoted strings with no escapes. Strings are restricted to the stated token/time/hex alphabets. Integers are decimal with no sign or leading zero except literal 0. Integers <=9007199254740991, no exponent; this avoids cross-language precision loss. These restrictions apply to this persistent format, not arbitrary owner source text.

An envelope is exactly ordered `{version:1,lineage:Token,key_id:Token,sequence:UInt,previous:Hex64,kind:Kind,payload:Payload}`. The notation names keys but the stored representation is ordinary compact JSON with quoted keys. Token is base64url without padding, 1..128 ASCII bytes. Hex64 is 64 lowercase hexadecimal digits. Instant is a real UTC `YYYY-MM-DDTHH:MM:SSZ`. Sequence begins at 1 and strictly increments by 1 for **all** control kinds; 0 denotes genesis. One fixed key/lineage per v1 stream; control-key rotation/compaction is unsupported until separately documented. Key loss/substitution is closed, never integrity reset.

Payload exact keys in exact order:

| kind | payload |
| --- | --- |
| operation_reserved | `{operation_id:OpID,recorded_at:Instant}`; OpID is authenticated server-issued content-independent identity under the corrected MCP contract; no caller label, digest, source/person/result link. |
| source_deleted | `{ref:SourceID,state:"deleted",recorded_at:Instant,deleted_at:Instant}`; only baseline-permitted per-source fields. Each immutable source ID in approved family scope gets a separate deletion record. |
| domain_revision_reserved | `{domain_revision:UInt,recorded_at:Instant}`; positive consecutive independent domain watermark, see domain-watermark.md. |
| grant_revoked | `{grant:Token,state:"revoked",recorded_at:Instant}`; random non-semantic grant reference, no source/person map retained on deletion. |

Production SourceIDs and eligibility-grant references are independently server-generated random identifiers, never model strings. A declared family is resolved and version-checked before the authorized operation; family/source-person associations are not preserved in the control payload after erasure. A logical deletion of a family may span several control frames; the service stays CLOSED until its entire approved scope and all derived cleanup are enforced. A durable prefix is never rolled back; interruption completes the remaining scope from protected pending operation state or remains closed if that state cannot be recovered. Never acknowledge partial scope as completed deletion. Protected pending scope is private, scrubbed after enforcement, excluded from content export, and must be carried into the current recovery kit transaction before the first scope frame; a lost partial-operation scope blocks activation. V1 therefore bounds family deletion to at most 100 source IDs. Before the first scope frame, durably write kit pending.json as ordered compact JSON {body:{version:1,lineage:Token,key_id:Token,operation_id:OpID,first_sequence:UInt,refs:SourceID[1..100],recorded_at:Instant},mac:Hex64}; refs are unique and byte-lexically sorted. MAC is HMAC-SHA256(K, ASCII GRM-CONTROL-PENDING-1, zero byte, exact body bytes). File <=16 KiB; atomic file/fsync/rename/directory-fsync protocol, no unknown fields. Validate it under the same lineage/key and approved exact plan scope before appending. Remove/fsync kit directory only after all listed source IDs have valid durable denial frames and matching enforced checkpoints. A crash with pending file requires finishing listed denials; inconsistent/missing committed scope keeps CLOSED. This temporary control file contains only random source IDs, operation ID and control metadata, no excerpts/person attribution, and is scrubbed before deletion acknowledgement; it is not retained per-source deletion metadata. A second family operation cannot replace a pending file.

Let `P` be exact envelope bytes. `L` is unsigned 8-byte big-endian byte length of P. Reject L>65536 before allocation; total frame length is `8 + L + 32`. MAC domain D is literal ASCII `GRM-CONTROL-FRAME-1` followed by one zero byte (00). Tag `T = HMAC-SHA256(K, D || L || P)`, with random 32-byte K held only in protected current kit/control custody. Frame is `L || P || T`. There is no envelope authenticator property; the single authenticator is T outside P. Verify framing/MAC before treating payload as authority; a bounded minimal parser may identify format/key but cannot trigger effects.

Genesis head is SHA256 of ASCII `GRM-CONTROL-GENESIS-1`, zero byte, ASCII lineage, zero byte, ASCII key_id. At sequence n, envelope.previous equals genesis (n=1) or prior head. New head is SHA256 of ASCII `GRM-CONTROL-HEAD-1`, zero byte, **entire frame including length and tag**. This is not a source-content hash. Reject lineage/key/sequence/previous mismatch, complete invalid MAC, malformed canonical bytes or unknown kind even with a valid MAC. A complete valid frame past the saved head is durable pending control work and must reconcile forward, never be dropped.

Head body fixed ordered fields: `{version:1,lineage:Token,key_id:Token,sequence:UInt,head:Hex64}`. Head/witness file is compact ordered JSON `{body:<body>,mac:Hex64}` with no newline. MAC is HMAC-SHA256(K, ASCII `GRM-CONTROL-CHECKPOINT-1` || zero byte || exact head-body bytes), hex encoded lowercase. Kit head, each required witness and SQLite applied-control checkpoint represent the same sequence/head. The witness uses the same authenticated bytes; copying an old valid file does not establish freshness. A separately current surviving witness/custody is mandatory; coordinated rollback of all copies remains undetectable. Witness-head reading does not disclose K to model/host.

Only a genuinely truncated final frame may be removed in exclusive recovery, and only beyond every witnessed/applied/acknowledged head. A complete frame with bad authenticator is corruption, not a truncatable suffix. A valid durable frame beyond any saved head is reconciled forward. Never truncate a frame required by a witness or erase reservation knowledge. Unknown/inconsistent state keeps all content access closed. File paths/mount/owner checks and fsync/rename ordering remain as in operations.

## One global control head, separate domain revision

SQLite stores `applied_control_sequence/head`, distinct from monotonic `domain_revision`. An accepted reservation advances the control head without asserting a CRM domain commit. Before model invocation or preview persistence: serialize control append, durably append reservation and advance kit plus every required witness; then one SQLite transaction inserts content-free reservation and advances applied-control checkpoint. Only after that transaction may planning begin. Kit/witness latency counts inside the existing prepare deadline. Witness failure means no model/preview/domain effect, closed pending reconciliation.

Crash before SQLite reservation commit: startup imports all valid kit reservations as unknown-outcome/unavailable and advances applied-control checkpoint. It never infers committed or starts extraction. A normal same-session attempt may retry only if an eligible durable prepared plan/verified terminal error exists; a missing row is unavailable, not a heuristic fresh operation. Crash after reservation transaction but before prepared preview similarly yields unavailable once the active attempt is lost. A verified model failure with no domain effect may preserve an explicit retryable failed state while its current durable state remains available; after rollback/loss of that detail only the reservation survives. Domain commit and known committed receipt remain atomic. Current kit is required for every new accepted operation, not just deletion; quickstart must disclose this availability cost.

Backup/export freezes a coherent domain snapshot **and** current control sequence under serialized publication. Reservations in the kit but absent from content snapshot are enumerated in portable reservations; the snapshot's old list cannot replace current authority. A newer control head invalidates unpublished output until revalidated/rebuilt, even if the change was only a reservation. Same-lineage import preserves every current reservation as non-executable; no false commit is inferred from reservation existence.

## Bound admission and control growth

Per lineage v1 limits: 100000 permanent operation reservations, 1000000 total control frames, 512 MiB log bytes, 32 active prepared plans, 10 new accepted reservations/minute with burst 10. Ordinary reservations may use at most 448 MiB of the 512 MiB log ceiling; the remaining 64 MiB is denial/recovery headroom. Check all bounds plus predicted frame bytes and <=80% utilization on every configured kit/witness volume **before** reservation. Reserve 64 MiB independent kit space for denials, pending control recovery and administrative completion; ordinary operation admission cannot consume it. Denials consume reserved space; insufficient durable reserve closes serving without false acknowledgement. Stop new admission instead of expiring reservations/denials. No unreviewed rotation/compaction or automatic new-lineage rollover.

Prepared plan expiry removes private content, never the reserved identity. Allocation of stateless authenticated tokens is separately rate-limited to 30/minute and creates no permanent reservation; return safe resource error before logging caller content. All media waits count inside operation deadlines. Qualification records actual bytes/frame, kit growth per accepted operation and fsync timing, including worst supported overlap. Capacity planning reports expected operations/day and remaining admission lifetime; no indefinite storage claim or new purchase is authorized.

All model/host processes share the same eight-core whole-host CPU allocation, not eight dedicated cores each. Permit at most one internal inference job and one host generation; they may overlap only within that shared allocation. Host background agents/alternate models are disabled. Qualification must measure the worst permitted overlap plus storage/control-media waits against the unchanged deadlines and memory caps. If this fails, qualification fails; no assumption that idle-host timings establish fit or that extra cores/hardware may be acquired.

## Crash-durable export and closed importer

Use owner-only staging on the configured local same filesystem, exclusive creation/no symlink following. Write each of six complete streams, fsync every stream; compute exact bytes/count/hash; write manifest last, fsync manifest and staging directory. Hold privacy/control publication barrier, verify eligibility/current head still matches, atomically rename staging into an unused final directory name, fsync final parent directory, then report success. An existing target is never overwritten. Crash recovery quarantines incomplete staging/final-directory uncertainty, never reports a valid completed export merely because a pathname exists. Concurrent denial invalidates and purges affected unpublished staging before acknowledgement; previously delivered owner copy remains separate.

Importer accepts exactly manifest.json plus the six named regular files. Reject symlinks, devices, sockets, directories within bundle, extra files, hardlink/path aliases and changed inode/size during verification. Bound entire bundle <=2 GiB, manifest <=64 KiB, each JSONL line <=256 KiB, total rows <=500000 plus reservations <=100000; validate counts/bytes before allocation and domain corpus ceilings before activation. No archive extraction, arbitrary caller paths or executable entries. Verify exact stream checksum/count/size, then real calendar/sequence/version/span/identity/claim/reference integrity in quarantine. Reject duplicate ID/version tuples, cyclic/self-referential correction tuples and foreign lineage. Manifest checksums do not authorize evidence or provide current control state. Unknown eligibility denies content; current kit/witness always dominate import fields. Source locators/timecodes and claim-specific speaker roles are authoritative; derived fragment IDs/indexes regenerate. No unexported authoritative fragment-only attribution field is permitted.

## Encrypted owner-key policy and provisioning

Supported provisioning is **import of an owner-preprovisioned conforming key**, not a generic Go marshal helper or runtime shell command. The helper accepts exactly one OpenSSH Ed25519 private key with cipher aes256-ctr, KDF bcrypt, rounds 64..1024, salt 16..64 bytes and total encoded file <=16 KiB. Reject plaintext/other algorithms/formats, multiple keys, duplicate/trailing objects, unreasonable length/work before expensive unlock. Inspect bounded unencrypted container metadata using reviewed OpenSSH format parsing; do not implement a new cipher/container. Use selected x/crypto/ssh v0.59.0 to parse/unlock; after parsing require Ed25519, consistent public/private pair and equality to enrolled current public key. Wrong passphrase or key gets safe denial, no secret diagnostics. The container's KDF metadata is not inferred from parser success. This supersedes any suggestion that library defaults provision the required rounds.

Unlock only through real controlling terminal; no stdin pipeline, arguments, environment, MCP/model/host cache or server signer. Never cache unlocked signer between operations. Key policy fixtures cover weak/excessive rounds, salt/file size, wrong cipher/type/key/passphrase, malformed/trailing material and correct import. Imports do not change public enrollment automatically. Protected trusted setup/revocation outside MCP binds verification-key version/epoch/session; missing current state blocks grants/restores. Same-UID/root compromise remains outside the declared isolation guarantee. Exact dependency identity is in dependencies.md; actual parser/provisioned-key compatibility and grant signature behavior remain later qualification evidence.

## Synthetic vectors

[Control byte vectors](control-vectors.md) define a public synthetic key, exact canonical payload/frame/tag/head/checkpoint for the original three record kinds plus the fourth-kind continuation and a signed-message canonicalization example. They are documentation arithmetic, not a backend/prototype or signature-validation pass. Independent re-review must check them against this grammar; implementation must consume these fixed fixtures rather than regenerate its own oracle. Required negative mutations: length, tag/payload, sequence, lineage, kind, previous head, unknown/duplicate field, noncanonical whitespace/escape/number, complete invalid frame and each truncated boundary. Retain current-policy/access/kit and baseline semantics; a correctly authenticated record alone does not grant new owner intent.
